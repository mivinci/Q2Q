# 直播阶段方案

状态：待实现。文件发布、可靠下载和 VOD 已验证读取在 SDK PR #48 中完成；直播作为后续独立 PR 推进。

## 目标与边界

发布者持续产生分段，订阅者发现最新索引，通过 P2P 或 CDN 获取并验证分段。SDK 负责身份、索引验证、分段传输、缓存和生命周期；编码、封装、解码及播放器由应用处理。第一版只支持单发布者、单订阅游标和固定滑动窗口。

现有 Seed 描述固定长度、固定 Merkle 根的内容，不修改其含义。直播索引引用独立分段的 Seed/info_hash，分段复用现有块校验和持久化能力。索引发现、动态持有者宣告和多分段上传仍需新增接线，不能仅把现有下载 API 包装一层。

## 协议草案

### 身份与发布轮次

- 流描述包含协议版本、发布者公钥和随机流标识；stream ID 从带域分离的规范编码派生，订阅入口固定绑定预期公钥。
- 同一流的发布重启采用递增 epoch，每轮包含随机 session ID；段序号在轮内单调递增。发布者持久化 epoch 和索引版本，避免重启复用旧序号。
- epoch/version 在签名后才具有身份意义；接收端持久化已接受的最高值。公钥轮换第一版视为新流，不隐式信任索引内的新公钥。

### 分段与窗口快照

- 分段项包含 epoch、段序号、媒体时间戳、时长、长度、Seed/info_hash；时间单位和字段上限必须在协议落地前固定。
- 内容元数据必须足以按现有 Seed 校验完整性。CDN/证明地址只是来源提示，其被签名也不代表响应字节可信。
- 第一版使用有大小上限的完整窗口快照，包含 stream ID、epoch/session ID、递增 revision、签发时间、过期时间、首尾序号、分段列表和结束标记。暂不做增量索引。
- 每个 revision 发布后不可修改；重叠窗口内同一段的身份与内容描述不可改变。拒绝重复、倒序、越界、不连续序号和超过窗口/字节上限的索引。媒体时间轴不连续需要显式标记。

### 签名与新鲜度

- 使用现有 Ed25519 能力，但为直播定义独立签名域、版本和确定性字段编码，不直接签随字段顺序变化的普通 JSON。
- 签名覆盖身份、轮次、revision、时间、窗口、分段元数据及结束状态；先检查编码大小、字段上限和预期身份，再验证签名，最后更新本地最高版本。
- 拒绝过期、超出允许时钟偏差、低于已接受 epoch/revision，以及同版本不同内容的快照。已收到最终结束标记后，不接受该轮继续追加。
- 首次订阅没有历史最高版本，只能结合签名有效期与本地时钟限制旧快照的可接受时间；恶意发现服务仍可隐藏更新或拒绝服务，签名不能证明拿到的就是最新索引。跨设备/清空本地状态后的强新鲜度保证留待后续协议设计。

## SDK 与服务职责

- `q2q-core`：网络无关的直播描述、窗口快照、规范编码、签名输入和验证状态机。
- `q2q-track`：流发现与索引定位所需的协议 DTO 和状态；具体采用索引内联还是地址定位，在实现接线前比较消息上限和刷新成本后确定。
- `q2q-punch`：继续负责连接同意和信令；新增消息只有在实际需求明确时加入。
- `q2q`：发布与订阅句柄、后台索引刷新、分段调度、P2P/CDN 回退、缓存回收、事件与取消。API 名称在协议类型稳定后确定。
- 保持源码和测试目录扁平，SDK 测试继续放在 `crates/q2q/tests`。

## 生命周期与调度

- 发布顺序：完成分段并生成校验元数据 → 确保至少一个来源可获取 → 宣告持有 → 发布签名索引。索引不能引用仍在写入的可变文件。
- 播放优先获取当前分段，再获取前向缓冲；限制连接数、在途字节、缓存大小和索引刷新频率。复用块租约，防止 P2P/CDN 重复提交。
- 旧段退出窗口后撤销持有宣告；只有没有读取引用和在途磁盘操作时才能回收。现有单文件 Publication 限制需扩展为有界的多分段服务能力。
- 订阅者落后于窗口时返回明确的窗口过期事件，由配置选择报错或跳到安全直播位置，不能静默把不同媒体位置拼接成连续字节。
- 区分暂时断流、索引过期、来源不可用、窗口过期和发布者签名结束。直播不能把暂时无数据当 EOF；只有已验证结束状态且尾段消费完毕才结束订阅。
- Drop/取消停止索引刷新、连接与分段任务，已开始的阻塞磁盘操作可完成。恢复时重新验证缓存及已保存的版本状态。
