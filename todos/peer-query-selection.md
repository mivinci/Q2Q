## 实现与兼容

- `q2q-track::selection` 保持系统/网络无关，复用两个后端的有序 query 原语；内存索引改为 BTreeMap 范围定位，避免每批从头扫描。
- 首次使用随机 Peer ID 起点；v1 不透明游标保存起点、最后扫描位置、绕回阶段，并绑定文件/请求者。旧 Peer ID 游标继续字典序扫描，不绕回。固定索引下不会跨页重复，实时索引不提供快照。
- 每批最多 64 个存储候选，每请求最多处理 512 个存储返回的在线候选；过期过滤仍由后端执行。预算耗尽可返回空页及后续游标，不承诺扫描全部索引或返回满额。
- HTTP 仍默认 10、裁剪到 1–50；SDK 本地拒绝非法值，query(hash) 签名保持不变。新增 QueryOptions / query_with_options、Builder::peer_query_limit（默认并发两倍，显式配置 1–50）及 BuildError::InvalidPeerQueryLimit。穷举匹配错误需增加分支。
- SDK 初次与定时发现使用同一 limit，连接上限不变；刷新开启新轮换，不自动追完所有页。上轮“最多保留 32 个候选”现在是默认推导上限，显式配置最多 50。
- 新游标需按不透明字符串传回，不能再将返回值解析成 Peer ID。请求者自身不再出现在 HTTP 查询结果中。
