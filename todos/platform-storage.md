# 平台存储与上传闭环

## 分阶段范围

1. 当前实施：项目级存储空间页面、平台 S3 配置与本地 R2 模拟绑定、本地持久化与 owner 接入权限。
2. 后续：上传任务、分片直传、取消与完成确认，将上传对象固定为不可变来源。
3. 后续：原生任务生成 Seed/Merkle 证明，成功后发布内容版本；失败可重试，不把上传完成当作内容已验证。
4. 后续：自带 S3 存储、长期凭据加密与轮换、短期下载授权刷新。

平台存储通过通用 S3 接口接入，R2 作为兼容服务参与验证；本地 R2 模拟提供开发路径，不创建远端 Bucket 或订阅套餐。连接状态表示项目接入配置，不表示实时健康探测，也不表示已购买容量。额度、计量和上传在接通前不展示虚构数字。

## 当前模型与权限

- storage_connection 归属于项目；第一阶段 provider 使用 platform-s3，同一项目最多一个平台连接。
- 所有成员可查看当前项目存储；只有 owner 可启用。每次写请求从登录用户和 projectId 重新验证成员及角色，不信任提交的 Cookie 或角色。
- 启用使用唯一约束和幂等插入，重复提交不创建多条连接。操作只登记项目配置，不创建云资源或开放 Bucket。
- 远端 Bucket 由平台通过 S3 endpoint 与凭据管理，本地模拟使用 Workers binding，不让用户提交 Bucket 名称或对象路径。后续对象键在服务端按项目和上传 ID 生成，所有对象操作都须先校验成员及资源归属。
- D1 表的连接 ID 不等于内容 ID；存储来源与 Seed 内容身份分离，项目共享与跨项目去重另行设计。

## 上传边界

- 上传会话登记期望字节数、项目、连接、对象键及过期时间；幂等完成和取消分别定义。
- 大文件直传使用 S3 multipart 与短期授权；R2 Workers binding 本身不等于浏览器可用的 S3 签名凭据。生产直传还需 S3 凭据及 CORS 配置，本地开发需等价适配，不能悄悄让所有大文件经过业务 Worker。
- 完成后由服务端核实对象大小和版本；对象存在或 ETag 都不能替代内容根校验。禁止以用户可修改路径作为已发布内容的长期来源。
- D1 与对象存储之间没有跨服务事务，需定义上传过期清理、孤立对象清理、完成确认重试和任务幂等键。

## 上传阶段实施约定

- 8 MiB 分片，浏览器最多并发 3 片；技术单文件上限 8 GiB，本地适配上限 64 MiB。套餐单文件限制由项目 entitlement 决定：Free 2 MiB，Creator/Team 8 GiB。暂不接收空文件。
- 生产由平台签发有效期不超过 10 分钟的 S3 UploadPart URL，绑定对象键、multipart ID、片号、Content-Type 和准确 Content-Length。长期凭据仅服务端持有。
- 本地仅在 Vite dev 且 UPLOAD_LOCAL_PROXY=true 时接受分片字节，经显式本地路由写入模拟 R2；生产构建没有此数据路径回退。
- D1 记录上传生命周期：initializing → uploading → completing → uploaded；uploading 与取消通过条件更新互斥。完成冻结分片清单，重复完成从同一对象恢复并验证大小及任务元数据，保存 object version 和 ETag。
- uploaded 仅表示对象已存储；后续独立的种子处理任务负责生成 Seed 与证明，不自动 announce 或公开原文件下载。
- 取消先持久化逻辑状态，再终止 provider multipart；失败保留 cleanupPending，界面可重试清理。已进入 completing 的任务只能重试完成，不能被取消线程删除。
- 上传会话一天过期；页面刷新不恢复文件句柄或已发送分片，未完成任务可取消，completing 可重试确认。初始化与完成跨服务崩溃、过期及孤立对象的定时清理仍需后续任务，不宣称后台清理已实现。

### 通用 S3 接线

- 所有远端配置统一采用 S3_ENDPOINT / S3_REGION / S3_BUCKET / S3_ACCESS_KEY_ID / S3_SECRET_ACCESS_KEY / S3_FORCE_PATH_STYLE。
- R2 不再是控制面中的特殊分支；创建、签名、完成、HEAD 校验、取消与删除均使用同一 S3 配置。支持路径式与虚拟主机式寻址，移除 Cloudflare Account ID 和域名硬编码。
- 上传任务固定 endpoint、region、bucket 和寻址方式，配置变更后拒绝混用已有 multipart ID。存储 provider 通过新增迁移转换为 platform-s3，保留连接 ID 和上传引用。
- S3 未返回 version ID 时保存 null，依靠唯一不可复用对象键和 ETag 约束当前来源，不能伪造原生 R2 version。

### 文件资源与上传会话

- 已拆出 file_record；文件 ID 保持稳定，上传会话通过 fileId 关联。取消只结束会话，文件仍可重试；浏览器重传入口要求名称/大小匹配并沿用 fileId。
- POST /api/files 创建文件，POST /api/files/:id/uploads 创建上传，POST /api/uploads/:id/parts 签发分片链接，POST /api/uploads/:id/complete 完成确认，DELETE /api/uploads/:id 取消。
- GET /api/files 和 GET /api/files/:id 查询项目文件，DELETE /api/files/:id 删除当前尚未发布的文件。所有操作验证成员关系，写操作要求文件创建者或 owner。
- 新会话、文件删除通过 D1 条件更新互斥；唯一索引限制每个文件一个活跃上传，完成时原子更新上传与文件状态。删除拒绝活跃上传和待清理状态，保留删除墓碑供重试。
