# 平台种子生成与 Wasm

后续阶段：[内容发布与下载授权](platform-publication.md)。

## 已确认方向

- 把与 I/O 无关的增量构建逻辑放到 q2q-core，SDK 及平台共用；不在 TypeScript 重写哈希或种子协议。
- q2q 保留文件读取、来源变化检查及做种；薄 Wasm crate 负责 JS 绑定。
- 平台服务端读取 S3 字节流，分段调用 Wasm，保存 Seed 与独立叶子哈希表。第一版可下载 Seed 内嵌叶子表，暂不开放公开来源 URL。浏览器计算结果不能直接当作服务端验证结果。
- 先验证 Wasm 兼容性和资源开销，再确定后台任务的分段、租约及重试实现；暂不新增原生任务服务。

## 实施顺序

1. core 增量构建器：任意切片输入、协议分块、长度校验、Seed 输出；SDK 复用。
2. Wasm 适配：隔离本地磁盘和系统随机数，生成 TypeScript 绑定，在 JS 运行时验证结果与资源开销。
3. 平台后台任务：固定 S3 来源版本，流式读取，持久化任务状态及处理产物。

## 边界

- 输入长度不足或超出声明长度都不能产出成功结果；切片边界不能改变内容身份。
- 内存不随文件字节数增长，但叶子表和 Merkle 计算仍随块数增长；不宣称常量内存。
- Wasm 不负责网络、凭据、D1 或 S3；平台绑定与任务调度不进入 core。
- 种子中的 proof_list/CDN 地址必须可长期解析并支持授权刷新，不把短期 S3 URL 固化为发布地址。
- 本地 Wasm 基准不代表 Cloudflare CPU 计费或线上运行限制已验证。

## 平台接线

- `@q2q/wasm` npm 工作区包提供 JS、类型及 `module.wasm` 导出，生成目录为 crate 内忽略的 pkg；业务代码不访问 Cargo target。
- 页面 Worker 在上传完成后登记 D1 intent 并发往 Cloudflare Queue，独立消费入口仍在 apps/platform 内。Vite 页面开发与完整 Workers 联调分开，启动方式见平台 README。
- 消费任务固定上传 ID、对象版本、ETag 和存储配置；流式计算，通过 leaseToken、120 秒租约、续约及条件提交抵御重复消息和过期任务。
- 产物使用每次尝试独立的对象键；提交 ready 前保存对象，并记录种子大小、SHA-256 摘要及 info_hash。提交结果不确定时先读取 D1 状态，不能删除可能已提交的产物。
- 详情展示状态、进度、内容身份和重试；成员可下载种子，写操作限创建者或 owner。下载前限制读取大小并校验摘要，处理期间禁止删除。
- 目前消费端支持通用 S3；本地 R2 上传代理不提供处理能力。下载的 Seed 内嵌叶子表，没有自动做种或公开 CDN 来源，不能将「种子已生成」表述为「已上线可分发」。

### 验证与剩余边界

- 真实浏览器通过生产构建的本地 workerd 上传 9 MiB 合成文件，自动入队，消费端读取测试 S3 并完成种子生成；实际下载的 Seed 与本地原始文件重新计算结果逐字节一致。
- 本地 SQLite + 模拟 S3 + 真实 Wasm 验证输出、重复处理、来源变化、存储失败、丢失提交响应、租约被替换、租约过期及已删除文件边界；没有使用认证令牌或外部服务。
- 修复 aws4fetch 请求使用 redirect:error 在 workerd 中创建 Request 失败的问题；改为 manual，所有调用仍拒绝 3xx，不携带签名跟随跳转。
- 平台类型检查、页面构建及消费端 Wrangler dry run 通过。新增 CI 接线，未运行远端 CI。
- 浏览器从失败状态点击重试后重新入队并完成，摘要校验版本的种子下载成功，和原始文件重算的结果一致。用户明确选择保留 `q2q-seed-processing-test.bin` 的 9 MiB 本地测试记录及 S3 原文件、种子、证明，供查看界面。
- 还需线上验证 Queue 和 CPU 额度；定时补发丢失的入队通知、强制终止后的孤立产物扫描、跨账号故障注入尚未覆盖。当前由持久任务状态与人工重试恢复，没有宣称完全自动恢复。
