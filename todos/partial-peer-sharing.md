# 下载中共享已验证块

## 目标与边界

普通下载和 VOD 可主动开启共享。首个块通过根校验并完成数据与恢复记录提交、上传入口就绪后，向 Track 宣告部分持有；后续块通过 Peer `Have` 更新；完整文件同步后升级 complete。Track 不保存块位图。

共享由独立句柄管理，下载完成不隐式停止共享；关闭共享不取消下载。取消或失败时撤销共享，恢复时仅宣告重新校验的块。复用 Client 上传连接、速率和磁盘读取预算，不允许稀疏空洞或未验证块上传。

## 阶段

- [x] 1. 上传源抽象与存储接线：复用校验 proof、可用块通知、按 info_hash 路由多个内容、独立清理。
- [x] 2. 部分 Peer 调度：Bitfield / Have、按可用块领取、有界等待、补充发现、完整源和 CDN 兜底。
- [x] 3. 高层 API 与自动宣告：首块发布、完成升级、续期撤销、普通下载及 VOD、独立共享句柄。

## 验收

- A 完整源，B 部分下载，C 从 B 下载已验证块；B 新增块后 C 无需重连即可通过 Have 取得。
- 未提交块不可读；篡改、截断、恢复证明失效不可上传。
- 多内容独立路由、共享关闭不影响其他内容，所有内容共享上传预算。
- 共享取消、下载失败、完成升级、断点恢复、阻塞磁盘任务的清理顺序。
- 保持现有低层 serve_file 签名兼容，目录保持扁平。


## 实现结果

- `upload_source.rs`：内部来源接口（Seed、可用块订阅、共享读取预算、读取数据与证明），完整文件和下载目标分别实现。
- `download_store.rs`：内存仅保存块到有界恢复记录偏移的索引，恢复时重建；提交数据与 receipt 同步后才可上传。上传再次校验字节与证明。
- `upload_router.rs`：Client 级单读取者，票据校验后按 info_hash 分发有界邮箱；最多 32 个不同内容，同哈希重复注册返回 AlreadyPublishing。关闭一项不影响其余项，最后一项退出才关闭共享接入。
- `discovery.rs`：统一普通下载与 VOD 的候选刷新和退避，优先完整来源，仍可连接部分来源；每五秒补充当前 Track 页，最多保留 32 个候选。
- `scheduler.rs`：单连接仅领取初始 Bitfield / 后续 Have 中可用的块；无有用任务最多等三秒，释放名额，五秒后可重试。已有数据接收时也处理 Have，完成前等待最后的 BlockDone 和结束握手。
- `Publication` 同时管理完整源和下载源；首块持久化后部分宣告，最终同步后升级 complete，不按块请求 Track。块通知不重置持有续期的计时器，等待首块期间也保持心跳。
- 普通下载新增 `download_shared` / `resume_download_shared`，返回 `(Transfer, Publication)`；VOD 新增 `.share(true)`、`sharing()`、`take_sharing()`。默认不共享；关闭上传不取消下载，下载取消/失败会撤销共享；成功下载后可继续保留上传句柄做种。
- Source / tests 目录保持扁平；不修改线协议，不增加 crate 或缓存。原低层 serve_file 签名保留。

## 当前边界

- Track 仍无分页；候选不是稀有块优先，完整来源优先。整文件下载在无活动连接且十秒无新块时结束 P2P 阶段，再按既有规则进入 CDN 或报错；VOD 持续刷新，单次读取仍受 read_timeout 约束。
- 下载目标的上传读与下载写仍在目标锁下串行；完整源继续使用按偏移并发读取，两类来源复用 Client 上传额度。后续可按性能数据优化目标读取，不引入未验证字节可见窗口。
- Publishing 包括等待首块；独立共享句柄返回不表示已被 Track 索引。失败通过其上传进度和 close 报告；撤销请求失败时远端记录依赖 TTL 清理。
- 有意不做自动无限后台做种，应用必须保留上传句柄。未完成 reader 退出即取消下载，其共享也会撤销，即便已经 take_sharing。
