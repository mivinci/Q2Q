# Web 客户端

主站客户端代码位于 `apps/www`，面向本机文件分享和种子下载，无平台账号登录。
主站分享/P2P 页面已上线；跨设备浏览器矩阵仍未完成，Mac Safari 接收 iPhone Safari 分享的失败正在排查。文档中的新增诊断能力对应开发版本，上线前线上页面不会出现。

## 分享本机文件

1. 点击“分享文件”（或拖入普通文件），核对文件名/大小与前台运行提示。
2. 点击“开始分享”。SDK 在本机分块生成种子、验证内容并宣告来源，不把文件上传到平台存储。
3. 等待“等待接收”后点击“保存种子”，把 `.q2q` 文件交给接收方。
4. 保持页面打开。任务详情显示真实发送量/连接数；暂停撤回来源，继续会重新宣告，停止释放上传资源。

发送量不是接收方校验完成率，因此分享不显示“文件已送达百分比”。没有接收方是等待状态，不是错误。
分享任务不持久化 File、原种子、账号凭据或私钥；刷新/关闭页面后不会继续做种，也不会把旧任务显示为仍在线。
重新分享需要重新选择文件。本机分享种子含内容身份和文件名，可被接入相同网络的下载者使用；发送种子前自行确认访问范围。

## 打开种子下载

选择/拖入 `.q2q` → 本地解析与预览 → 点击“开始下载”。来源连接、P2P、HTTP 回退、逐块验证、检查点均由 SDK 处理。
只有 Peer 来源的种子也可以开始，找不到可用来源会提示错误；来源离线不代表种子损坏。
连接详情只显示 SDK 的 P2P 控制会话状态，“在线”不代表文件字节一定来自 P2P，也不虚构 TURN 实际通路。

## 用磁力链下载

“下载”按钮同时接受 `.q2q` 种子和 Q2Q 磁力链（`magnet:?xt=urn:sha256:…`）：粘贴链接 → 获取元数据 → 预览 → 开始下载。
磁力链只携带内容身份，文件名、大小和校验数据来自在线 Peer 提供的经验证元数据；因此至少需要一个在线来源，
且元数据获取受 60 秒预算限制。只支持 `urn:sha256`，BitTorrent 的 `btih`/`btmh` 链接会明确报错。
仅有平台/CDN 存储、没有在线 Peer 的内容不能靠磁力链冷启动，仍需完整 `.q2q` 种子。

- 页面只连接构建配置的 Track，不使用链接中的 `tr` 提示；链接里的 `dn` 显示名也不会被采信或用于命名文件。
- 未验证的元数据会被拒绝并换下一个候选；全部候选都失败时报“没有可用来源”，与“连接失败/超时”分开提示。
- 经验证的最小种子缓存在本机 IndexedDB（只存内容哈希与种子字节，不存链接或显示名）。刷新后“重新粘贴链接”会优先用缓存，
  不重新请求元数据；拿到同内容的 `.q2q` 种子也可以恢复同一任务。
- 分享行菜单的“复制磁力链”生成可粘贴的链接；自动复制失败时对话框会给出可手动复制的只读链接。
  生成的链接内容由种子内 Track 列表决定，接收方页面仍只使用自己的构建 Track。

已完成内容暂存于本机 OPFS，点击“保存文件”导出。支持原生文件保存选择器的环境走流式导出；其他环境仅对不超过
32 MiB 的文件使用有界 Blob 交给下载管理器，文案为“已提交浏览器保存”，不确认系统最终落盘。
刷新后下载历史仅是提示，需重新选择同一内容身份的种子（或重新粘贴同一磁力链），由 SDK 读回校验检查点再恢复。

下载完成**默认不继续分享**。用户在更多菜单明确点击“继续分享”后，SDK 会重验完整缓存并宣告；活跃分享期间不能删除该缓存，
先停止分享再删除。该操作不删除已保存到其他位置的用户文件。下载中的部分块共享虽有 SDK API，页面本版不提供默认开关。

## 配置与运行边界

`PUBLIC_Q2Q_TRACK_URL` 通过 SvelteKit `src/env.ts` 声明为公开、构建期配置，默认 `https://track.q2q.app`；
空字符串关闭网络功能、保留 HTTP。测试可使用 HTTP loopback，公网必须 HTTPS；公开参数不是凭据，不能放 token。
浏览器只消费 Track 签名身份流程提供的显式 Punch WSS 入口，不在页面拼接地址或从种子隐式切换 Track。

本地 Chromium/WebKit 持久 profile 的实际页面验证了分享/保存种子/浏览器下载完整哈希、暂停/停止/刷新、显式缓存分享、
缓存保护、中英文/窄屏和已有 HTTP 恢复。Chromium ↔ 原生完整文件页面链路通过；WebKit/native ICE 仍未兼容，明确跳过。
不承诺 Safari.app、移动后台、跨 NAT、强制 TURN 或浏览器任意大文件容量；公网 SDK 成功也不等于主站 UI 已上线。


## 断线和重试

没有在线来源时，先确认分享方仍保持页面打开并处于等待接收/分享中，再点击下载任务的“重试”。
如需刷新后的恢复，重新选择同一内容身份的种子，SDK 会重验已提交字节，不能按同名文件猜测。

分享的控制连接断开会显示分享失败；它不是后台自动重连任务。网络或服务恢复后重新选择源文件、
明确开始分享。准备失败前未生成可用种子时，“保存种子”不可用；失败任务可移除后重新开始。
刷新活跃分享不会在新页面显示旧任务仍在线，远端残余记录可能等待 TTL 到期。

开发版的这些路径已在本机临时服务验过；跨设备、跨 NAT 和强制 TURN 当前暂未验收，不因“重试可用”
就承诺所有网络均可连接。


## 查看失败诊断（开发版本）

失败任务的“详情”菜单 → “传输详情”中可查看“连接诊断”。复制其中的错误码、阶段、
ICE/连接/通道状态及候选计数以协助排查；不要发送完整 SDP、Cookie、票据或 TURN 凭据。
诊断不含地址或凭据，不会自动上传，刷新后不保证保留。网络错误不等于跨域错误；
控制连接在线也不代表 WebRTC 已建连。同一 Wi-Fi 或 Edge 成功不能代替 Safari 双端验收。
